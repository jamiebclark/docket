# Data Model: Scheduler Screens and Media (003)

This builds on 002's schema (`src/server/db/schema/{accounts,media,posts,attempts}.ts`).

- One new migration, `drizzle/0002_*.sql`, is generated by `pnpm db:generate` from the schema changes below and committed.
- Every new or changed table is project-owned and listed in `src/server/db/project-owned.ts` with scope column `project_id`.
- Joins carry `a.project_id = b.project_id` (002 dal.md "join rule").

## Changed: `media_assets`

| Column | Type | Notes |
|---|---|---|
| *(existing)* `id`, `project_id`, `storage_key`, `public_url`, `mime_type`, `width`, `height`, `byte_size`, `alt_text`, `first_used_at`, `created_by_user_id`, `created_at`, `updated_at` | | unchanged |
| `thumbnail_storage_key` | `text` NULL | `projects/<pid>/media/<id>/thumb.webp`. NULL for 002-registered assets |
| `thumbnail_url` | `text` NULL | the public URL of the thumbnail |
| `original_filename` | `text` NULL | the client's file name, display and search only. Path stripped, control characters removed, ≤ 255 characters. Never used to build keys |
| `tags` | `text[]` NOT NULL DEFAULT `'{}'` | normalised by Zod (research D11) |
| `deleted_at` | `timestamptz` NULL | soft delete (research D10). Repositories hide deleted rows by default |

New constraints and indexes:

- `CHECK (cardinality(tags) <= 20)`.
- `media_assets_tags_gin` — GIN index on `(tags)`.
- `media_assets_live_idx` — on `(project_id, created_at DESC)` where `deleted_at IS NULL`.

The existing `UNIQUE (project_id, storage_key)` stays.

Semantics:

- **upright dimensions**: `width` and `height` are those of the stored (auto-oriented) file. `byte_size` and `mime_type` are those of the stored file, and `mime_type` comes from the decoder (`image/jpeg | image/png | image/webp`).
- **used**: `first_used_at IS NOT NULL`. It is set by `markUsed` on first attach and never cleared, so "unused" means never attached (spec assumption).
- **missing alt text**: `trim(alt_text) = ''`.

## New: `media_variants`

One derived, compliant copy of one asset for one constraint set (FR-014).

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK default `gen_random_uuid()` | |
| `project_id` | `uuid` NOT NULL → `projects.id` ON DELETE CASCADE | scope |
| `media_asset_id` | `uuid` NOT NULL → `media_assets.id` ON DELETE CASCADE | |
| `constraints_hash` | `text` NOT NULL | `sha256(canonicalJSON({v: VARIANT_PIPELINE_VERSION, ...constraints}))`, first 32 hex characters |
| `storage_key` | `text` NOT NULL | `projects/<pid>/media/<assetId>/v/<hash>.<ext>` |
| `public_url` | `text` NOT NULL | |
| `mime_type` | `text` NOT NULL | |
| `width`, `height` | `integer` NOT NULL, `> 0` | |
| `byte_size` | `integer` NOT NULL, `> 0` | |
| `steps` | `text[]` NOT NULL | the subset of `convert`, `downscale`, `compress` that was applied (shown as notes) |
| `created_at` | `timestamptz` NOT NULL DEFAULT now() | |

Constraints and indexes:

- `UNIQUE (media_asset_id, constraints_hash)` (`media_variants_asset_hash_uq`) — the cache key.
- `UNIQUE (project_id, storage_key)`.
- Index `(project_id, media_asset_id)`.

Lifecycle:

- A row is inserted after its object is stored (`ON CONFLICT (media_asset_id, constraints_hash) DO NOTHING RETURNING *`, then a re-select when nothing is returned).
- Rows are deleted with their asset (soft delete removes them explicitly; the FK cascade covers a project delete).
- There is no row when the original already complies (`plan.kind = "original"`).

## Unchanged tables this feature acts on

## Code-level entities (no table)

### `MediaConstraints` (`src/providers/media.ts`)

```ts
interface MediaConstraints {
  acceptedMimeTypes: readonly string[];   // capabilities.media.allowedMimeTypes
  outputMimeType: string;                 // capabilities.media.outputMimeType ?? acceptedMimeTypes[0]
  maxBytes: number;                       // capabilities.media.maxBytesPerFile
  minWidth?: number; maxWidth?: number;
  minHeight?: number; maxHeight?: number;
  minAspectRatio?: number; maxAspectRatio?: number; // width / height
  maxAltTextLength?: number;
}
```

- **Validation.** `mediaConstraintsOf` throws at registry load if:
  - `outputMimeType ∉ acceptedMimeTypes` or ∉ `{image/jpeg, image/png, image/webp}`;
  - any minimum exceeds its maximum;
  - `maxBytes ≤ 0` while `maxImages > 0`.
- `providers/registry.test.ts` asserts this for every registered provider.

Declared values in this feature:

| Provider | Declares |
|---|---|
| `mock` (existing caps) | accepted `image/jpeg`, `image/png`; output `image/jpeg`; 5,000,000 bytes; 4 images; no dimension or aspect rules |
| test "instagram-like" (tests only) | accepted `image/jpeg`; output `image/jpeg`; 8,000,000 bytes; width 320–1440; aspect 0.8–1.91; alt ≤ 1,000 |
| test "bluesky-like" (tests only) | accepted `image/jpeg`, `image/png`, `image/webp`; output `image/jpeg`; 2,000,000 bytes; 4 images |

The test values come from `docs/research/meta.md` and `bluesky.md`, as reproduced in the spec assumptions.

### `ImagePlan` (pure, `planImage(asset, constraints)`)

```text
original  — mime ∈ accepted ∧ bytes ≤ maxBytes ∧ dimensions within [min, max] ∧ aspect within range
derive    — fixable: mime not accepted → convert; width/height > max → downscale (keeps ratio);
            bytes > maxBytes → compress (may also downscale at generation time)
refuse    — aspect outside [minAspectRatio, maxAspectRatio]          → error aspect_ratio_out_of_range
            width < minWidth or height < minHeight                   → error image_too_small
            downscale to max would put the other side below its min  → error image_too_small
```

Evaluation order: refusals first (no partial plan), then derive steps in the order convert → downscale → compress.

Predicted output:

- dimensions = the `fit: inside` result of `maxWidth`/`maxHeight` without enlargement;
- mime = `outputMimeType` when converting, else the original;
- bytes = `min(original bytes, maxBytes)`, a prediction (the real value comes from generation).

## State notes

- **Media asset**: `live` → (`deleteMedia`) → `deleted`. Delete is refused while any target of a post using it is `scheduled | publishing | failed | ambiguous`. There is no undelete.
- **Variant**: absent → present (`prepareVariants` or the publish-time fallback) → absent (asset deleted). A changed constraint set means a new hash, so a new variant is made and the old row stays until the asset is deleted (it is harmless and small). A pipeline-version bump has the same effect.
- **Post target** transitions are 002's.
  - The new action `moveTargetToOccurrence` is `scheduled → scheduled`, with a new instant and `schedule_kind = 'slot'`. It is allowed from `slot` or `explicit`, never while leased.
  - "Mark as not published" = `resolveAmbiguous({ outcome: "failed" })` → `failed`, which can then be retried (002).
- **Social account**: `needs_reauth` → (`reconnectMock`, mock only) → `active`.
