# Data model: Video groundwork (018)

Phase 1 for [plan.md](./plan.md). One migration (`drizzle/0011_*.sql`, generated by `drizzle-kit generate` and committed). Every table here carries `project_id` and is read only through the scoped DAL (constitution III). Decisions referenced as P* are in [research.md](./research.md).

## 1. `media_assets` (existing, extended)

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `byte_size` | **`bigint`** (TS `number`, `mode: "number"`) | no | | Was `integer` (F2). The check `> 0` stays. Up to 4,294,967,296. |
| `kind` | `text` | no | `'image'` | `CHECK (kind IN ('image','video'))`. |
| `processing_state` | `text` | no | `'ready'` | `CHECK (processing_state IN ('processing','ready','failed'))`. Images are inserted `ready` (P7). |
| `processing_step` | `text` | yes | | `CHECK (processing_step IN ('queued','probing','poster'))`. Not null exactly when `processing_state = 'processing'`. |
| `processing_error` | `text` | yes | | Person-facing reason, ≤ 300 chars. Not null exactly when `failed`. Never holds ffmpeg output, keys or URLs. |
| `processing_attempts` | `integer` | no | `0` | Incremented at claim. Refunded on graceful shutdown (P8). |
| `processing_lease_until` | `timestamptz` | yes | | Worker lease (120 s, renewed every 30 s). |
| `processing_lease_token` | `uuid` | yes | | Guards every worker write after the claim. |
| `source_storage_key` | `text` | yes | | Staging object `projects/<p>/uploads/<u>/source`. Cleared when the item is ready or failed. |
| `duration_ms` | `integer` | yes | | Video only; ≤ 3,600,000. |
| `frame_rate` | `double precision` | yes | | Video only; `avg_frame_rate`, 3 decimals (P11). |
| `video_codec` | `text` | yes | | ffprobe `codec_name`, e.g. `h264`. |
| `audio_codec` | `text` | yes | | `null` on a ready video = no audio. |
| `container` | `text` | yes | | `CHECK (container IN ('mp4','mov'))`, from the sniff (P12). |

The meaning of the existing columns for a video:

- `mime_type`: `video/mp4` or `video/quicktime`. It is set from the declared type at completion and from the container when ready.
- `width` and `height`: **displayed** dimensions, with rotation applied. They are null until ready.
- `storage_key` and `public_url`: the final `original.mp4|mov` key and URL from insertion. The object exists only once the item is ready (P8).
- `thumbnail_storage_key` and `thumbnail_url`: the poster, set when ready.

New checks:

- `media_assets_video_ready_facts`: `kind <> 'video' OR processing_state <> 'ready' OR (duration_ms IS NOT NULL AND video_codec IS NOT NULL AND container IS NOT NULL AND width IS NOT NULL AND height IS NOT NULL)`.
- `media_assets_step_matches_state`: `(processing_state = 'processing') = (processing_step IS NOT NULL)`.
- `media_assets_error_matches_state`: `(processing_state = 'failed') = (processing_error IS NOT NULL)`.

New index: `media_assets_processing_idx` on `(created_at)` `WHERE processing_state = 'processing' AND deleted_at IS NULL`. It serves the worker's cross-project claim (P8).

### Processing state transitions (video)

```text
[upload completed] ──insert──▶ processing/queued
processing/queued   ──claim (attempts+1)──▶ processing/probing
processing/probing  ──probe+clean ok──▶ processing/poster
processing/poster   ──poster+store ok──▶ ready            (facts, poster, mime set; source deleted)
processing/*        ──any check or command fails──▶ failed (reason; source and written objects deleted)
processing/*        ──lease expires (crash)──▶ claimable again (step kept; next claim counts)
processing/*        ──graceful shutdown──▶ processing/queued (lease cleared, attempts−1)
claim with attempts = 3 ──▶ failed ("…after 3 attempts")
```

`ready` and `failed` are terminal. Deleting is `deleted_at`, as today, from any state (P27).

### DAL additions (`src/server/dal/media.ts`)

- `list(filter)` and `listIdsForSelection(filter)` gain `kinds?` and `states?` filters. `listIdsForSelection` always applies `kind = 'image'` and `state = 'ready'` (P25).
- `insert` accepts the new columns.
- `processingStatus(ids)` returns `{ id, kind, state, step, error, createdAt }` for live rows among `ids`.
- The worker repo `createMediaProcessingRepo(db)` is cross-project, used only inside `crossProject("media: process videos", …)`:
  - `claimNext(now)`;
  - `renewLease(id, token, until)` → boolean;
  - `release(id, token)`;
  - `finishReady(id, token, facts)` → boolean;
  - `finishFailed(id, token, reason)` → boolean.

  Every write after the claim is conditional on `processing_lease_token = token AND deleted_at IS NULL`.

Indexes:

- `media_uploads_member_open_idx` on `(project_id, created_by_user_id)` `WHERE state IN ('open','completing')`, for the per-member cap.
- `media_uploads_expiry_idx` on `(created_at)` `WHERE state IN ('open','completing')`, for housekeeping.

### Upload session transitions

```text
open ──completeUpload: lock row──▶ completing
completing ──parts missing / wrong size──▶ open          (error set; Retry sends the missing parts)
completing ──size mismatch / over limit / image refused──▶ refused   (aborted, staging deleted)
completing ──image processed / video row inserted──▶ completed       (media_asset_id set)
open | completing ──cancelUpload (owner)──▶ cancelled    (aborted, staging deleted)
open (age > MEDIA_UPLOAD_EXPIRY_HOURS) | completing (age > 1 h) ──housekeeping──▶ expired
```

Terminal states: `completed`, `refused`, `cancelled` and `expired`. They are kept for audit and debugging.

`completeUpload` on a `completed` session returns its asset (idempotent, P4). Sign, list or cancel on a terminal session returns the conflict "This upload has already finished".

### DAL (`src/server/dal/uploads.ts`, `createUploadsRepo(db, projectId)`, added to `ProjectScope` as `uploads`)

- `insert`;
- `getOwned(id, userId)`, live sessions of this project and member only;
- `lockOwned(id, userId)`, `FOR UPDATE` in its own statement;
- `countOpenFor(userId)`;
- `transition(id, from[], to, patch)` → boolean, a conditional update.

The cross-project housekeeping functions `listExpired(now, hours, limit)` and `markExpired(id)` live in `src/server/dal/uploads-housekeeping.ts` and are called only inside `crossProject("housekeeping: expire uploads", …)`.

`MembersRepo` gains `lockSelf(userId)`, which locks the caller's own `member` row with `FOR NO KEY UPDATE`. It serialises one member's concurrent `createUpload` calls for the cap (P2).

## 3. Provider-side types (`src/providers/types.ts`)

```ts
export type VideoContainer = "mp4" | "mov";

export interface VideoCapabilities {
  /** 0 = this provider does not accept video (yet). */
  maxVideos: number;
  /** A video may share a post with images. Default false. */
  withImages?: boolean;
  containers?: readonly VideoContainer[];
  /** ffprobe codec names, e.g. "h264". */
  videoCodecs?: readonly string[];
  audioCodecs?: readonly string[];
  /** A video with no audio stream is accepted. Default true. */
  silentAllowed?: boolean;
  maxBytes?: number;
  minDurationSeconds?: number;
  maxDurationSeconds?: number;
  minWidth?: number;
  maxWidth?: number;
  minHeight?: number;
  maxHeight?: number;
  /** width ÷ height of the displayed frame, inclusive. */
  minAspectRatio?: number;
  maxAspectRatio?: number;
  maxFrameRate?: number;
}

export interface ProviderCapabilities {
  text: { /* unchanged */ };
  media: { /* unchanged: images */ };
  video: VideoCapabilities;            // NEW, required
  textOnlyAllowed: boolean;
  postTypes: readonly PostType[];
}

export interface VideoFacts {
  container: VideoContainer;
  durationSeconds: number;
  frameRate: number | null;
  videoCodec: string;
  audioCodec: string | null;
}

export interface MediaItem {
  url: string; mimeType: string; width: number | null; height: number | null; bytes: number; altText: string;
  kind?: "image" | "video";             // NEW, absent = image
  status?: "processing" | "ready" | "failed"; // NEW, absent = ready
  failureReason?: string;               // NEW, set when failed
  video?: VideoFacts;                   // NEW, set on ready videos
}

export interface StepContent { text: string; mediaCount: number; videoCount: number } // videoCount NEW
```

Registry check: `mediaConstraintsOf` gains `assertVideoCapabilities(caps.video)`. The registry load test therefore rejects:

- `min > max` for any pair;
- a negative `maxVideos`;
- `withImages: true` with `media.maxImages = 0`;
- `maxVideos > 0` without `"video"` in `postTypes`.

## 4. Library limits and media status (`src/server/media/limits.ts`, served to the browser)

```ts
export interface LibraryLimits {
  image: { types: readonly string[]; typeLabels: string[]; maxBytes: number; maxMegapixels: number };
  video: { types: readonly string[]; typeLabels: string[]; maxBytes: number; maxSeconds: number; maxSide: number };
}

export interface MediaStatus {          // existing, extended; additions are NEW
  enabled: boolean;
  maxUploadBytes: number;               // = limits.image.maxBytes (kept for existing readers)
  maxMegapixels: number;
  acceptedTypes: readonly string[];     // = image.types ∪ video.types
  limits: LibraryLimits;                // NEW
  transport: "direct" | "via_app";      // NEW
}
```

The values come from:

- `image.types`: `UPLOAD_MIME_TYPES`;
- `video.types`: `VIDEO_UPLOAD_MIME_TYPES = ["video/mp4", "video/quicktime"]`, in `src/lib/media/types.ts`;
- `maxSide`: `VIDEO_MAX_SIDE = 4096`;
- the rest: `getEnv().media`.

`getEnv().media` gains `maxVideoBytes`, `maxVideoSeconds`, `uploadTransport`, `uploadExpiryHours` and `maxOpenUploads`. `getEnv().storage` gains `browserEndpoint?: string`.
