# Data model: Per-target video formatter

Phase 1 for `specs/024-video-target-formatter/spec.md`. Decisions P* are in [research.md](./research.md). One migration (`drizzle/0017_*.sql`, generated by `drizzle-kit generate`, with one hand-added `UPDATE`) adds two tables and new columns on two existing tables. `pnpm db:check` must pass.

## 1. `media_assets`: new facts (P9, FR-014)

| Column | Type | Null | Default | Meaning |
|---|---|---|---|---|
| `video_bitrate` | `bigint` (number mode) | yes | — | Video stream bits per second from ffprobe `bit_rate`. Null = not reported; the planner then falls back (P5). |
| `audio_bitrate` | `bigint` | yes | — | Audio stream bits per second. Null = no audio or not reported. |
| `audio_sample_rate` | `integer` | yes | — | Hz. Null = no audio. |
| `audio_channels` | `smallint` | yes | — | Null = no audio. |
| `index_at_front` | `boolean` | yes | — | `moov` before the first `mdat` (top-level box walk). Null = unknown, treated as false. |
| `facts_version` | `smallint` | no | `2` | `1` = recorded before this entry (rescan needed); `2` = current. |
| `facts_attempts` | `smallint` | no | `0` | Failed rescans; at 3 the planner refuses. |

**Constraints.**

- `media_assets_facts_version_valid`: `facts_version IN (1, 2)`.
- Positive-or-null checks on the four numbers.

**Migration.** Add the columns, then run `UPDATE media_assets SET facts_version = 1 WHERE kind = 'video'`. This is hand-added after the generated DDL, in the same file.

**Writers.**

- `MediaProcessingRepo.finishReady` writes all five facts and `facts_version = 2`.
- Two new token-guarded methods:
  - `claimRescan(now)` (P9): claims a ready, live, v1 video with `facts_attempts < 3`, preferring `first_used_at IS NOT NULL`. It sets the lease and increments `facts_attempts`.
  - `finishRescan(id, token, facts)`: sets the facts and `facts_version = 2`, and clears the lease.
- A failed rescan only clears the lease; the attempt is already counted.

**Read model.**

- `videoFieldsOf` (`src/server/media/item.ts`) adds the new facts to `MediaItem.video`.
- `VideoFacts` (`src/providers/types.ts`) gains the optional fields:
  - `videoBitrate?: number | null`;
  - `audioBitrate?: number | null`;
  - `audioSampleRate?: number | null`;
  - `audioChannels?: number | null`;
  - `indexAtFront?: boolean | null`;
  - `factsVersion?: 1 | 2`;
  - `factsUnreadable?: boolean`.
- Absent fields mean an item built by older code paths; the planner treats them as unknown.

## 2. `post_targets.video_wait_since` (P13, P15)

| Column | Type | Null | Meaning |
|---|---|---|---|
| `video_wait_since` | `timestamptz` | yes | Set by the claim-time video gate on the first wait. Its presence means "Preparing video for <platform>". |

- **Cleared** (set null) by:
  - the lease patch, when publishing starts;
  - any retry, requeue or reschedule (`retry.ts`, `retry-all.ts`, `scheduleAt`, `addToQueue`);
  - cancel;
  - the failure decision.
- **`TargetRecord` and `TargetPatch`** gain it.
- **`PostTargetView` and `PostViewTarget`** gain `preparingVideo: boolean`, which is `status = 'scheduled' AND video_wait_since IS NOT NULL`.

## 3. `post_video_edits` (P10, D1, FR-001)

One edit per video per post. No row = the default edit.

| Column | Type | Null | Default | Rule |
|---|---|---|---|---|
| `project_id` | `uuid` → `projects` cascade | no | | scope |
| `post_id` | `uuid` → `posts` cascade | no | | |
| `media_asset_id` | `uuid` → `media_assets` cascade | no | | must be attached to the post (service check) |
| `trim_start_ms` | `integer` | no | `0` | `>= 0`, `% 100 = 0` |
| `trim_end_ms` | `integer` | yes | | null = end of video; else `> trim_start_ms + 999`, `% 100 = 0` |
| `fit` | `text` | no | `'pad_blur'` | `IN ('pad_blur','pad_color','crop')` |
| `pad_color` | `text` | no | `'#000000'` | `~ '^#[0-9a-f]{6}$'` (stored lower case) |
| `focal_x` | `double precision` | no | `0.5` | `BETWEEN 0 AND 1` |
| `focal_y` | `double precision` | no | `0.5` | `BETWEEN 0 AND 1` |
| `recommended_shape` | `boolean` | no | `false` | |
| `updated_at` | `timestamptz` | no | `now()` | |

**Keys and listing.**

- Primary key `(post_id, media_asset_id)`.
- Index `(project_id, post_id)`.
- Listed in `src/server/db/project-owned.ts`.

**DAL** (`src/server/dal/posts.ts`, scoped):

- `listVideoEdits(postId) → Map<assetId, VideoEdit>`;
- `setVideoEdits(postId, edits: Record<assetId, VideoEdit>)`: upserts the given edits and deletes a row whose edit equals the default;
- `setMedia` also deletes edits whose asset is no longer attached.

**`VideoEdit`** (`src/lib/video/edit.ts`, client-safe):

```ts
type VideoFit = "pad_blur" | "pad_color" | "crop";
interface VideoEdit {
  trimStartMs: number;        // multiple of 100
  trimEndMs: number | null;   // null = end of video
  fit: VideoFit;
  padColor: string;           // "#rrggbb"
  focalX: number;             // 0..1 of the displayed width
  focalY: number;             // 0..1 of the displayed height
  recommendedShape: boolean;
}
const DEFAULT_VIDEO_EDIT: VideoEdit = { trimStartMs: 0, trimEndMs: null, fit: "pad_blur", padColor: "#000000", focalX: 0.5, focalY: 0.5, recommendedShape: false };
```

**Validation** (P21): `videoEditSchema` (zod) checks the shape. `assertEditFits(edit, durationMs)` checks:

- the end does not pass the duration;
- the kept part is at least 1 s;
- an end equal to the duration is normalised to `null`.

Errors use field paths `videoEdits.<assetId>.trimEndMs` etc.

## 4. `video_versions` (P11, D8–D13, FR-011, FR-015–FR-023, FR-033)

Adapted files and previews. Shared by every target whose plan gives the same key.

| Column | Type | Null | Notes |
|---|---|---|---|
| `id` | `uuid` pk | no | `gen_random_uuid()` |
| `project_id` | `uuid` → `projects` cascade | no | the video's project |
| `media_asset_id` | `uuid` → `media_assets` cascade | no | |
| `kind` | `text` | no | `IN ('full','preview')` |
| `key` | `text` | no | `videoRecipeKey(kind, recipe)`, 64 hex |
| `recipe` | `jsonb` | no | frozen `VideoRecipe` (§6); the worker builds only from this |
| `steps` | `text[]` | no | `VideoStep[]` |
| `state` | `text` | no | `IN ('queued','building','ready','failed')`, default `'queued'` |
| `attempts` | `smallint` | no | default 0 |
| `lease_until` | `timestamptz` | yes | |
| `lease_token` | `uuid` | yes | `(lease_until IS NULL) = (lease_token IS NULL)` |
| `error` | `text` | yes | `(state = 'failed') = (error IS NOT NULL)`; plain sentence, ≤ 300 chars |
| `due_at` | `timestamptz` | yes | earliest due time of a target that wants it; a preview's request time |
| `requested_at` | `timestamptz` | no | default `now()`; refreshed on every request or sync |
| `checked_at` | `timestamptz` | yes | last time housekeeping found it wanted |
| `storage_key` | `text` | yes | set when ready: `mediaKeys(p, a).videoVersion(key)` or `.videoPreview(key)` |
| `public_url` | `text` | yes | |
| `container` | `text` | yes | `IN ('mp4','mov')` |
| `width`, `height` | `integer` | yes | probed |
| `duration_ms` | `integer` | yes | probed |
| `frame_rate` | `double precision` | yes | probed |
| `video_codec`, `audio_codec` | `text` | yes | probed (`audio_codec` null = silent) |
| `video_bitrate` | `bigint` | yes | probed |
| `byte_size` | `bigint` | yes | probed |
| `finished_at` | `timestamptz` | yes | |
| `created_at`, `updated_at` | `timestamptz` | no | |

**Constraints and indexes.**

- Unique `video_versions_asset_kind_key_uq (media_asset_id, kind, key)`.
- Unique `(project_id, storage_key)`.
- Check `video_versions_ready_facts`: `state <> 'ready'` OR every probed column and `storage_key` is not null.
- Partial index `video_versions_claim_idx (due_at, created_at) WHERE state IN ('queued','building')`.
- Index `(project_id, media_asset_id)`.
- Index `video_versions_collect_idx (checked_at) WHERE state <> 'building'`.
- Listed in `project-owned.ts`.

**State transitions.**

```text
            claim (lease, attempts+1)
  queued ───────────────────────────────▶ building
    ▲  ▲                                   │  │  │
    │  │ lease expired (another lane)      │  │  └─ lost lease / asset deleted → (no write; uploaded object deleted)
    │  └───────────────────────────────────┘  │
    │        release (shutdown, attempts−1)   ├─ readback ok, lease held, asset live → ready
    │                                         └─ failure: attempts < 3 → queued (lease cleared)
    │                                                       attempts ≥ 3 → failed (error)
    ├── requeue: Retry / syncVideoVersions(requeueFailed) / object vanished at publish  ◀── failed | ready
    └── housekeeping delete (not wanted for 24 h, not building) → row and object removed
```

**Repositories.**

- **`createVideoVersionsRepo(db, projectId)`** (`src/server/dal/video-versions.ts`, scoped; used by services and housekeeping):
  - `getByKeys(pairs: {assetId, kind, key}[])`;
  - `ensureQueued(rows: {assetId, kind, key, recipe, steps, dueAt}[], opts: {requeueFailed?: boolean})`: `INSERT … ON CONFLICT (media_asset_id, kind, key) DO UPDATE SET requested_at = now(), due_at = LEAST(…)`, plus a reset of `failed` rows when asked;
  - `requeue(id)`;
  - `deleteForAsset(assetId) → storage keys`;
  - `listCollectable(before, limit)` and `markChecked(ids, at)`;
  - `delete(id)`.
- **`createVideoVersionProcessingRepo(db)`** (`src/server/dal/video-version-processing.ts`, cross-project, worker only, inside `crossProject("video: …")`), following entry 2's media repo:
  - `claimNext(now)`: `FOR UPDATE SKIP LOCKED`, ordered `due_at ASC NULLS LAST, created_at`. It joins the live asset, so a deleted asset is never claimed.
  - `renewLease`, `release`, `finishReady(id, token, facts)`: conditional on the token and the asset still live.
  - `finishFailed(id, token, reason)` and `retryLater(id, token)`: back to `queued`.
- **Claim-time reads** in `ClaimContext.videoGate` (`src/server/dal/scheduler.ts`) use the claim transaction's executor:
  - the video rows of the post;
  - `post_video_edits`;
  - `video_versions` by key;
  - an insert of a missing `queued` row.

## 5. Capabilities (P24, D7, FR-012)

`VideoCapabilities` (and therefore `VideoLimitOverrides`) gains:

```ts
/** Bits per second, decimal (25 Mbps = 25_000_000). */
maxVideoBitrate?: number;
/** Bits per second to encode audio at; not a refusal limit (D7). Default 128_000 when re-encoding. */
audioBitrate?: number;
/** Hz. Default 48_000 when re-encoding. */
maxAudioSampleRate?: number;
/** Default 2 when re-encoding. */
maxAudioChannels?: number;
/** width ÷ height; the shape used when reframing (D2). Must lie inside the merged aspect range. */
recommendedAspectRatio?: number;
/** The file's index (moov) must precede the media data. */
indexAtFront?: boolean;
```

`assertVideoCapabilities` refuses non-positive or non-finite values. It also refuses a `recommendedAspectRatio` outside `[minAspectRatio, maxAspectRatio]` of the merged block it is declared in. `videoLimitsFor` merges the new fields like the rest.

## 6. Planner types (P1–P8, `src/providers/video-plan.ts`)

```ts
export const VIDEO_PIPELINE_VERSION = 1;
export type VideoStep = "cut" | "crop" | "pad" | "resize" | "frame_rate" | "reencode" | "rewrap";

export interface VideoSource {
  width: number; height: number;          // displayed
  bytes: number;
  facts: VideoFacts;                      // incl. the new optional facts
}

export type FrameOp =
  | { kind: "none" }
  | { kind: "crop"; x: number; y: number; w: number; h: number }
  | { kind: "pad"; canvasW: number; canvasH: number; frameW: number; frameH: number; x: number; y: number; fill: "blur" | `#${string}` };

export interface VideoRecipe {
  mode: "rewrap" | "encode";
  container: "mp4" | "mov";
  startMs: number; keptMs: number;        // encode only; rewrap keeps the whole file
  frame: FrameOp;
  width: number; height: number;          // output, even when encoding
  frameRate: number | null;               // null = unchanged
  video: { maxBitrate: number | null; maxBytes: number | null; minWidth: number; minHeight: number };
  audio: { sampleRate: number; channels: number; bitrate: number } | null;  // null = silent
  indexAtFront: boolean;
}

export interface PlannedVideo {           // what the provider's validation sees for `derive`
  container: VideoContainer; videoCodec: string; audioCodec: string | null;
  width: number; height: number; durationSeconds: number; frameRate: number | null; maxBytes: number | null;
}

export type VideoPlan =
  | { kind: "original" }
  | { kind: "derive"; mode: "rewrap" | "encode"; steps: VideoStep[]; recipe: VideoRecipe; output: PlannedVideo; notes: ValidationIssue[] }
  | { kind: "refuse"; issues: ValidationIssue[] }
  | { kind: "checking"; notes: ValidationIssue[] };

export function planVideo(src: VideoSource, limits: VideoCapabilities, edit: VideoEdit,
                          ctx: { index: number; platform: string; typeLabel?: string }): VideoPlan;
export function previewRecipe(full: VideoRecipe): VideoRecipe;   // ≤ 640 px long side, ≤ 30 fps, no byte fitting
```

**Issue codes.**

- **Refusals** reuse the existing codes: `video_too_short`, `video_too_small`, `video_container_not_allowed` (no producible container) and `video_too_large` (the P8 floor).
- **New:** `video_facts_unreadable`.
- **Notes**, all severity `info`: `video_will_cut`, `video_will_crop`, `video_will_pad`, `video_will_resize`, `video_will_change_frame_rate`, `video_will_reencode`, `video_will_rewrap` and `video_checking`.

## 7. Storage keys (F16)

`mediaKeys(projectId, assetId)` gains:

- `videoVersion: (key: string) => \`${base}/vv/${key}.mp4\``. A `mov` rewrap uses `.mov`, chosen by the recipe's container.
- `videoPreview: (key: string) => \`${base}/vp/${key}.mp4\``.

Both sit next to the original in the same public bucket, and both are deleted with the video (`deleteMedia` → `videoVersions.deleteForAsset`).

## 8. Environment (P22)

`VIDEO_ENCODE_CONCURRENCY: int(1, 4, 1)` in `src/server/env.ts`, exposed as `getEnv().media.videoEncodeConcurrency`, and documented in `.env.example`.

## 9. Heartbeat

The worker's version loop writes `writeHeartbeat("video", at, counts)`, where counts are `{ built, failed, previews }`, at most once a minute. `ClaimContext.videoGate` reads its age for the "worker not running" reason (P13).
